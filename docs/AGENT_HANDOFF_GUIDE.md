# Техническое руководство и Handoff-документ для ИИ-агентов: `repOx` (v0.3.3)

Этот документ предназначен для быстрой и точной передачи архитектурного, алгоритмического и продуктового контекста проекта **`repOx`** другому ИИ-агенту или инженеру.

---

## 1. Обзор проекта и структура Workspace

**`repOx`** — сверхбыстрый CLI и интерактивный TUI-инструмент на Rust (2024 Edition) для упаковки исходного кода репозиториев и мультимодальных пайплайнов в оптимизированные контекстные промпты для LLM и видео-генераторов (Claude Fable 5.1, GPT-6 Luna, Gemini 3, DeepSeek R1, Llama 4, Grok Video, Kling, Sora, Veo, Wan 2.1) за миллисекунды (<15–30 мс на тысячах файлов), без внешних runtime-зависимостей.

### Структура Cargo Workspace (`resolver = "3"`, `version = "0.3.3"`):
- **`repox-cli`** (`src/main.rs`, `src/cli.rs`) — бинарный крейт `repox`. Парсинг аргументов (`clap`), инициализация логирования (`tracing`), маршрутизация между headless-пайплайном, компилятором видео-промптов (`--video-prompt`, `--video-anchor`, `--shot-duration`) и интерактивным TUI, работа с буфером обмена (`arboard` + ANSI OSC 52 fallback для SSH/tmux).
- **`crates/repox-core`** — библиотечное ядро без привязки к UI:
  - `domain.rs` — доменные типы (`ScanOptions`, `RepoFile`, `ScanSummary`, `OutputFormat`, `TokenProfile`).
  - `scanner.rs` — многопоточный обход дерева каталогов, git-интеграция и конвейер чтения/трансформации файлов.
  - `filter.rs` — эвристический фильтр шума, секретов, бинарников и минифицированных бандлов.
  - `outline.rs` — лексический экстрактор архитектурных сигнатур (`--outline` / `--signatures-only`).
  - `lockfile.rs` — умный суммаризатор lock-файлов (`--summary-locks`).
  - `budget.rs` — автоматический оптимизатор и укладчик репозитория в жёсткий бюджет токенов (`-b, --budget` / `--max-tokens`).
  - `redact.rs` — однопроходный лексический сканер и маскировщик захардкоженных секретов и API-ключей (`-r, --redact-secrets`).
  - `video.rs` — ИИ-компилятор видео-промптов (`--video-prompt`, `--shot-duration`), экстрактор самого резкого хвостового кадра видео через FFmpeg и 60% center-crop дисперсию 3x3 лапласиана (`extract_sharpest_tail_frame`, `--video-anchor`) и минификатор/дебаггер графов ComfyUI.
  - `git.rs` — Git-aware фильтрация изменённых/staged файлов и генерация unified diff (`-m, --modified`, `--staged`).
  - `tokenizer.rs` — параллельный BPE-подсчёт токенов (`tiktoken-rs`) и профили контекстных окон LLM.
  - `formatter.rs` — генераторы выходных форматов (`xml`, `markdown`, `tool-call` / `json`).
- **`crates/repox-tui`** — интерактивный терминальный интерфейс (`ratatui` + `crossterm` + `nucleo-matcher`):
  - `tree.rs` — плоская арена дерева файлов `FlatTree` (`Vec<Node>`) с $O(1)$ операциями свертки и каскадными чекбоксами без аллокаций в цикле рендеринга.
  - `app.rs` — состояние TUI, нечеткий поиск (`nucleo-matcher`), генерация воспроизводимой CLI-команды (`Shift+C`).
  - `ui.rs` — рендеринг двухпанельного интерфейса (в `stderr`), прогресс-бар контекстного бюджета и лексическая подсветка синтаксиса в окне предпросмотра.

## 2. Как работает `repOx` шаг за шагом (Dataflow Pipeline)

Весь цикл работы `repOx` спроектирован вокруг минимизации системных вызовов, отсутствия блокировок (lock-free batching) и нулевых лишних аллокаций:

```
[CLI Args / Git Diff Filter]
          │
          ▼
1. ignore::WalkBuilder (параллельный обход ФС с учётом .gitignore / .repoxignore)
          │
          ▼
2. Heuristic Pre-Filter (отсев секретов, lock-файлов, бандлов, проверка размера и 8KB NUL-байт)
          │
          ▼
3. Content Transform (чтение UTF-8, опционально: --outline сжатие сигнатур или --summary-locks)
          │
          ▼
4. BPE Tokenization (Rayon par_iter + tiktoken-rs: cl100k_base / o200k_base + оценка стоимости)
          │
          ├──► [Headless Mode] ──► Formatter (XML / Markdown / Tool-Call JSON) ──► stdout / file / Clipboard (arboard + OSC 52)
          │
          └──► [Interactive TUI (-i)] (рендеринг в stderr через Ratatui + FlatTree Arena)
                      │
                      ├──► [c / Enter] ──► Formatter ──► Clipboard / stdout
                      └──► [C (Shift+C)] ──► Экспорт воспроизводимой CLI-команды (repox -I ...)
```

### Пошаговый разбор архитектуры:

1. **Параллельный обход (`ignore::WalkBuilder` + `Rayon`)**:
   - Используется многопоточный work-stealing итератор из крейта `ignore` (движок `ripgrep`).
   - На лету применяются правила `.gitignore`, `.ignore`, глобального gitignore и кастомного `.repoxignore`, а также пользовательские глобы (`-I/--include`, `-e/--exclude`).
   - Если переданы флаги `-m/--modified` или `--staged`, `repox-core::git` предварительно запрашивает у Git список затронутых путей и unified diff, ограничивая сканирование релевантными файлами.

2. **Многоступенчатый эвристический фильтр (`filter.rs`)**:
   - **Метаданные до чтения диска**: проверка размера файла (`-s/--max-file-size`, по умолчанию `1MB`), отсев директорий `.git`, `node_modules`, `target`, `.venv`, `dist`, `build`.
   - **Защита секретов (Security-first)**: автоматическая блокировка `.env*` (кроме `.env.example`), приватных ключей (`*.pem`, `*.key`, `*id_rsa*`, `*id_ed25519*`), сертификатов и кредов (`credentials.json`, `.npmrc`, `.pypirc`).
   - **Проверка бинарности за 1 syscall**: читается заголовок файла и проверяется наличие `NUL`-байта (`\0`) в первых 8 КБ (стандартная эвристика Git), а также валидность UTF-8.
   - **Детектор минифицированного кода**: анализируется средняя и максимальная длина строки (если строка превышает порог минификации, например в `*.min.js` или скомпилированных ассетах, файл отбрасывается).

3. **Трансформация контента (`outline.rs` и `lockfile.rs`)**:
   - Если включён `--summary-locks`, вместо пропуска lock-файлов парсер извлекает из них только список `пакет @ версия`, а для графов ComfyUI — параметры разрешения, сэмплера, чекпоинтов и промптов.
   - Если включён `--outline` (`--signatures-only`), потоковый лексический анализатор со счётчиком баланса скобок/отступов вырезает тела функций и методов, оставляя только архитектурный каркас.

4. **Параллельная BPE-токенизация (`tokenizer.rs`)**:
   - С помощью `rayon::prelude::*` и синглтонов `tiktoken-rs` (`cl100k_base` и `o200k_base`) токены всех файлов подсчитываются параллельно на всех ядрах CPU.
   - Поддерживаются профили современных моделей (`fable` — 1M, `luna` — 1.05M, `gemini` — 1M, `claude` — 200k, `o1` — 200k, `deepseek` — 128k, `llama` — 128k) с расчётом процента заполнения окна.

5. **Zero-Allocation Ratatui TUI (`crates/repox-tui`)**:
   - Иерархия файлов укладывается в плоский вектор `FlatTree` в порядке прямого обхода (pre-order traversal). Любое поддерево — это непрерывный срез `nodes[idx..subtree_end]`.
   - Переключение папки (`Space`) обновляет флаги выбора во всём срезе поддерева и пересчитывает агрегированные суммы токенов/байтов обратным проходом без единой кучи-аллокации (` Box`/`Rc` отсутствуют).
   - Весь TUI рендерится строго в `stderr`, оставляя `stdout` чистым для UNIX-пайпов (`repox -i | llm ...`).

## 3. Пять механизмов экономии 60–90% токенов в `repOx`

`repOx` спроектирован так, чтобы максимизировать **отношение сигнал/шум (SNR)** в контекстном окне LLM за счёт 5 комплементарных механизмов:

### Механизм 1: Автоматическая фильтрация мусора, ассетов и бандлов (до 40–70% экономии на «сыром» репо)
Исключает `node_modules`, `target`, SVG-графику, sourcemaps (`*.map`), бинарные файлы (8KB NUL-byte check) и минифицированные JS/CSS бандлы (детекция сверхдлинных строк).

### Механизм 2: Архитектурное сжатие сигнатур `--outline` / `--signatures-only` (60–90% экономии на исходном коде)
Вырезает тела функций и методов, заменяя их на `{ /* ... */ }` (или `...` для Python), сохраняя комментарии документации, импорты, определения типов (`struct`, `enum`, `trait`, `interface`, `class`) и сигнатуры функций. Поддерживает **Rust, Python, Go, TypeScript/JavaScript, C/C++, Java**.

```bash
# Сжать весь репозиторий до архитектурного каркаса и скопировать в буфер обмена
repox --outline -c
```

Пример трансформации Rust-кода в режиме `--outline`:
```rust
pub struct Scanner {
    options: ScanOptions,
}

impl Scanner {
    pub fn new(options: ScanOptions) -> Self { /* ... */ }
    pub fn scan(&self) -> Result<ScanReport, ScanError> { /* ... */ }
}
```

### Механизм 3: Умная суммаризация Lock-файлов `--summary-locks` (до 98% экономии на графе зависимостей)
Сырой `Cargo.lock` или `package-lock.json` может занимать 30 000–80 000 токенов. По умолчанию `repOx` пропускает их, но если LLM нужно знать точные версии библиотек, флаг `--summary-locks` парсит `Cargo.lock`, `package-lock.json`, `pnpm-lock.yaml`, `poetry.lock`, `yarn.lock` и `go.sum`, превращая их в компактный список `pkg @ version`:

```bash
repox --summary-locks -c
```
Вместо тысяч строк TOML/JSON модель получает компактный блок `<file path="Cargo.lock.deps.txt">`:
```text
clap @ 4.5.32
ratatui @ 0.30.0
rayon @ 1.10.0
tiktoken-rs @ 0.6.0
```

### Механизм 4: Git-Aware упаковка диффов `-m, --modified` и `--staged` (75–95% экономии при код-ревью и отладке)
При написании PR или исправлении бага не нужно отправлять весь репозиторий. `repOx` запрашивает состояние Git и упаковывает **только изменённые или индексированные (staged) файлы** вместе с блоком `<git_diff>` (unified diff):

```bash
# Упаковать только текущие незакоммиченные изменения + git diff
repox -m -c

# Упаковать только staged-файлы для генерации описания PR или ревью
repox --staged -c
```

### Механизм 5: Интерактивная тактильная селекция в TUI (`-i`) + экспорт CLI-команды (`Shift+C`)
Позволяет визуально увидеть самые «тяжёлые» папки и файлы (рядом с каждым узлом отображается размер и число токенов), мгновенно отключить лишние подсистемы клавишей `Space`, отфильтровать файлы через нечёткий поиск `/` (`nucleo-matcher`) и нажать `C` (`Shift+C`), чтобы скопировать готовую воспроизводимую CLI-команду для скриптов или агентов.

## 4. Что реализовано в релизах v0.1.0, v0.2.0 и v0.3.3

### Базовый фундамент (v0.1.0)
- Многопоточный сканер (`ignore::WalkBuilder` + `rayon`) с поддержкой `.gitignore`, `.ignore`, `.repoxignore`.
- Защита от утечки секретов и 8KB NUL-byte детектор бинарных файлов.
- Офлайн-подсчёт токенов (`tiktoken-rs`) с профилями моделей (`fable`, `luna`, `gemini`, `claude`, `o1`, `deepseek`, `llama`, `cl100k`).
- Интерактивный TUI (`ratatui` на `stderr`) с плоской ареной `FlatTree`, трёхсоставными чекбоксами `[x]`/`[-]`/`[ ]`, нечётким поиском `nucleo-matcher` и `TerminalGuard` (RAII восстановление терминала при панике).
- Форматы вывода Claude XML (`-f xml`) и collision-safe Markdown (`-f md`).
- Генерация автодополнений оболочки (`--completions zsh|bash|fish|powershell|elvish`).

### Возможности v0.2.0
1. **Экстрактор архитектурных сигнатур (`--outline` / `--signatures-only`)**:
   - Модуль `crates/repox-core/src/outline.rs`.
   - Поддержка Rust, Python, Go, TypeScript/JavaScript, C/C++, Java с корректной обработкой строковых литералов, комментариев и вложенных блоков.
2. **Синтетический формат вызова инструментов агента (`-f tool-call` / `-f json`)**:
   - Генерирует JSON-массив объектов ответа инструмента `read_file` (`role: "tool"`, `tool_call_id`, `name: "read_file"`, `path`, `content`), а также виртуальные элементы для `.repox_structure` и `.git_diff`. Идеально подходит для инжекции контекста в агентские циклы (OpenAI/Anthropic/Ollama tool harnesses).
3. **Умный суммаризатор lock-файлов (`--summary-locks`)**:
   - Модуль `crates/repox-core/src/lockfile.rs`.
   - Извлекает детерминированные списки `name @ version` из `Cargo.lock`, `package-lock.json`, `pnpm-lock.yaml`, `poetry.lock`, `yarn.lock`, `go.sum`.
4. **Git-aware упаковка контекста (`-m, --modified` и `--staged`)**:
   - Модуль `crates/repox-core/src/git.rs`.
   - Фильтрация дерева файлов по статусу Git и автоматическое включение unified diff патча в выходной промпт (`<git_diff>` в XML, секция `# Git Diff` в Markdown, `call_git_diff` в ToolCall JSON).
5. **Улучшения TUI и кроссплатформенного буфера обмена**:
   - Клавиша **`C` (`Shift+C`)** в TUI: генерирует и копирует воспроизводимую CLI-команду (`repox -I path/to/file1 -I path/to/file2 ...`), соответствующую текущему выбору пользователя.
   - **Поддержка ANSI OSC 52**: автоматический fallback записи в буфер обмена через управляющие последовательности терминала при работе по SSH, в контейнерах или внутри `tmux`.
   - **Лексическая подсветка синтаксиса в TUI**: раскраска ключевых слов, строк, комментариев и типов в панели предпросмотра (`crates/repox-tui/src/ui.rs`) без просадки FPS.

### Новые возможности (v0.3.0 — v0.3.3)
1. **ИИ-компилятор видео-промптов, экстрактор якоря и дебаггер графов ComfyUI (`crates/repox-core/src/video.rs`)**:
   - **`optimize_video_prompt` / `optimize_video_prompt_with_duration` (`--video-prompt <PROMPT>`, `--shot-duration <SECONDS>`)**: компилирует сырые описания сцен в структурированные промпты для **Grok Video, Kling, Sora, Veo и Wan 2.1** с настраиваемой длительностью шота (по умолчанию `5s`, либо через `--shot-duration`). Формирует **двойной вывод (dual output)**:
     1. Структурированный XML-бриф (`<video_prompt_compiler>`, `<character_lock>` с фиксацией субъекта, оптики `35mm`/`85mm`/`anamorphic` и освещения, а также блоки `<shot index="N" duration="Xs">`) для LLM-генераторов промптов и агентных пайплайнов.
     2. Секцию чистых, готовых к вставке строк сэмплера без XML-тегов (tag-free sampler strings), где в каждом клипе принудительно повторяется полная строка идентичности персонажа (subject + lens + lighting) для сохранения визуальной консистентности между генерациями.
   - **`extract_sharpest_tail_frame` (`--video-anchor <CLIP.mp4>`)**: извлекает 24 последних кадра видеоклипа с помощью `ffmpeg`, применяет сглаживание шумов (denoising) и оценку резкости по центральному кропу 60% (`compute_frame_sharpness` / `select_sharpest_frame` через дисперсию дискретного оператора Лапласа 3x3 `[0, 1, 0; 1, -4, 1; 0, 1, 0]` за <1 мс на кадр), сохраняя самый резкий хвостовой кадр без motion blur в `<clip>.anchor.png` для бесшовной склейки мульти-шот видео (Image-to-Video anchor).
   - **`summarize_comfyui_workflow`**: автоматически распознаёт JSON-графы ComfyUI (как UI-формат с `"nodes"`/`"links"`, так и API-формат с `"class_type"`) и сжимает 30 000-токенные графы виджетов в компактный отсортированный манифест, извлекая разрешение и тайминг (`width`, `height`, `length`/`frames`, `fps`), полную конфигурацию сэмплера (`steps`, `cfg`, `sampler_name`, `scheduler`, `seed`), чекпоинты/модели и позитивные/негативные промпты (экономия 85–95% токенов при `--summary-locks`).
2. **Автоматический укладчик бюджета токенов (`crates/repox-core/src/budget.rs`, `-b, --budget` / `--max-tokens`)**:
   - Функция `apply_token_budget` гарантированно укладывает любой репозиторий в заданный лимит токенов (поддерживаются суффиксы `50k`, `100k`, `1m`).
   - Двухфазная стратегия сохранения информации: сначала второстепенные и самые тяжёлые файлы прогрессивно переводятся в режим архитектурных сигнатур (`extract_outline`), сохраняя точки входа (`main.rs`, `lib.rs`, `index.ts`) и файлы из `git diff` в полном виде; только если этого недостаточно, наименее приоритетные файлы (тесты/фикстуры) исключаются из тела промпта, оставаясь в дереве `<repository_structure>`.
3. **Потоковый сканер и редактор секретов (`crates/repox-core/src/redact.rs`, `-r, --redact-secrets`)**:
   - Однопроходный лексический анализатор `redact_secrets(content) -> (String, usize)`, обнаруживающий и маскирующий захардкоженные ключи внутри исходного кода на `[REDACTED_SECRET]`:
     - Ключи OpenAI (`sk-...`, `sk-proj-...` от 20 символов)
     - Ключи Anthropic (`sk-ant-...` от 20 символов)
     - Токены GitHub (`ghp_...`, `gho_...`, `github_pat_...` от 20 символов)
     - Ключи доступа AWS (`AKIA` + 16 заглавных алфавитно-цифровых символов)
     - Блоки приватных ключей PEM/OpenSSH (`-----BEGIN ... PRIVATE KEY-----`)

## 5. Примеры использования CLI для ИИ-агентов

```bash
# 1. Сформировать JSON-массив tool-call ответов только по изменённым в Git файлам
repox -m -f tool-call -q

# 2. Уложить весь репозиторий строго в бюджет 50 000 токенов с маскировкой секретов
repox --budget 50k --redact-secrets -c

# 3. Скомпилировать мульти-шот видео-промпт (8-секундные шоты) и извлечь самый резкий хвостовой кадр в <clip>.anchor.png
repox --video-prompt "Please generate a video of a samurai in bamboo forest on 85mm anamorphic lens. Then he draws his katana in slow motion." --shot-duration 8 --video-anchor shot1.mp4

# 4. Получить высокоуровневую карту архитектуры большого репозитория (сигнатуры + зависимости + параметры ComfyUI графов)
repox --outline --summary-locks -f xml -o arch_context.xml

# 5. Подготовить контекст для ревью staged-изменений с точным подсчётом токенов под Claude Fable
repox --staged -t -p fable -c
```

## 6. Дорожная карта (Roadmap v0.4.0+)

Следующие итерации развития `repOx` сфокусированы на глубокой интеграции с автономными ИИ-агентами:

1. **Режим MCP-сервера (`repox --mcp` / Model Context Protocol)**:
   - Встроенный JSON-RPC 2.0 сервер поверх `stdio`, предоставляющий инструменты `repox_map_repo`, `repox_pack_diff`, `repox_optimize_video_prompt` и `repox_read_files` напрямую в Claude Desktop, Cursor, Zed и кастомные агентские рантаймы.
2. **Конфигурационные пресеты `.repox.toml`**:
   - Поддержка декларативных профилей на уровне репозитория (`[profiles.backend]`, `[profiles.video]`, `[profiles.review]`), задающих списки `include`/`exclude`, `budget = "64k"`, `redact_secrets = true` и целевой формат вывода.
3. **Граф импортов и ранжирование по связности (PageRank / Dependency Centrality)**:
   - Оценка архитектурной важности файлов на основе локальных `use` / `import` / `#include` связей для ещё более точной приоритизации файлов в `budget.rs`.
